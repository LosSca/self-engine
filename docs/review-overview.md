## 一、运行时结构

```
浏览器 (React)
  ├─ GameCanvas ── 文字输入 / 战斗按钮 / 地图点击 / 背包使用
  ├─ WorldStudio ─ 地点·物品·门·实体·事件·任务·行动·调试
  └─ KnowledgeStudio ─ 知识·模式·剧情线·模型预设
        │
        ▼
FastAPI
  ├─ /api/v1 …… 规则链路（确定性）
  └─ /api/game … 旧聊天链路（流式叙事；绑定世界的冒险会转交规则链路）
        │
        ▼
ActionService.execute  ← 唯一状态写入口
  1 载荷校验与 request_id 幂等
  2 RulesEngine 判定（纯函数，无模型）
  3 效果 → 事件固定点 → 任务 → 剧情线
  4 知识上下文（深度/剧情/聚焦/预算/NPC 可见性）
  5 叙事（模型只能描述已结算结果；失败只记录）
  6 单事务提交 state + request + domain events（版本 CAS）
        │
        ▼
SQLite
  scenarios.db   情景·知识·剧情线·模型预设
  game_state.db  权威状态快照·请求记录·领域事件·快照
  events.db      旧链路事件流·记忆晶体
  traces.db      LLM 调用追踪
```

关键不变量：

- 模型不写状态；叙事失败不回滚回合。
- 条件、效果、后续事件都是校验过的数据，不存在脚本或 `eval`。
- 事件、任务奖励、剧情推进在同一回合内按固定点收敛，同一事件每回合最多尝试一次。
- 地图点击、结构化按钮与自然语言共用同一个 `ActionRequest` 管线。

## 三、本轮新增（在 `1d0fec3` 之上）

### 事件多分支结果

- `GameEventDef.branches[]`：按顺序求值，首个条件全部满足的分支把效果与后续事件**追加**到基础效果。
- 无条件分支作为兜底，且必须放在最后；引用、条件、效果在保存与调试时都校验。
- 分支效果失败仍整事件原子回滚，并运行事件的失败后续。
- 执行记录与模拟结果返回 `branch` 标签，便于定位“这次走了哪条路”。

### NPC 知识可见边界

- 知识条目新增 `audience_npc_ids`；空表示公开。
- 行动叙事时，聚焦集合包含当前位置、在场存活 NPC 与本次目标；只有集合中的 NPC 命中受众时才注入该条目。
- 被隐藏的条目在预览统计中带有明确排除原因；编辑器可设置并在列表中显示“仅 X”。

### 编辑器

- 事件编辑器新增结果分支（标签、条件、效果、后续事件）。
- 知识编辑器新增限定 NPC；上下文预算与预览聚焦词延续上一轮。

## 四、风险登记

| 优先级 | 风险 | 影响 | 现状与缓解 |
|--------|------|------|-----------|
| P0 | 旧聊天链路仍存在独立的流式副作用路径 | 未绑定世界的冒险与绑定世界行为不同 | 绑定世界后前端与后端都转向规则链路；旧链路保留兼容，未删除 |
| P1 | 地图有坐标但无寻路 | 大地图只能逐出口移动 | 地图导航只展示相邻出口；跨区域旅行仍需逐段移动 |
| P1 | 服务无鉴权 | 本机/局域网内任何客户端可调用调试接口 | 回滚/修复受 `ENGINE_DEBUG_TOOLS` 开关限制；默认仅本机使用 |
| P1 | SQLite 单写者 | 高并发回合会以版本冲突重试 | CAS 保证不丢更新；压力场景应换 Postgres |
| P2 | 知识无语义召回 | 条目很多时依赖标签与字符预算 | 聚焦 + 预算已限制上下文规模；可后续接向量检索 |
| P2 | 模型预设只覆盖叙事 | intent/judge 仍用全局模型 | 预设表已有 role 字段，接口可扩展 |
| P2 | 长期记忆只在旧链路 | 引擎战役没有自动摘要 | NPC 摘要隔离已修复；接入引擎链路需新调度点 |
