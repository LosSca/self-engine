# 阶段 5：地图可视化编辑（WorldMapGraph）

## 目标

让"世界地图"从卡片列表变成可操作的图：能看见地点之间的连线、门与钥匙关系，
能直接点节点进编辑器、点连线删出口。不引入绘图库，也不做自由画布引擎。

## 实现

新增 `frontend/src/components/WorldMapGraph.jsx`，挂在 `WorldStudio` 的「世界地图」标签页里，
位于原有卡片列表上方（卡片列表保留，作为无障碍与批量核对视图）。

### 布局

`layoutNodes(locations, startId)` 是纯函数，从起点做 BFS 分层：

- 深度 = 从起点经过几条出口；同一深度排成一列；
- 起点不可达的地点不会消失，统一放到最后一列（"孤岛"也能被看见和编辑）；
- 坐标为 `PAD + depth * (NODE_W + GAP_X)`、`PAD + index * (NODE_H + GAP_Y)`，
  所以同一份世界定义每次都画出同一张图。

拖动节点只改本地显示：位置存 `localStorage` 的 `lunar.map.positions.<worldId>`，
「重置布局」清空。**地图布局不是权威游戏数据**，不进世界定义、不进存档。

### 边（出口）

每条 `ExitDef` 画一条带箭头的线：

- 实线 = 可通行；红色虚线 = 该出口挂了未开启的门；
- 线上标 `label` 或目标 id，带门的再加锁标记；
- 点击连线选中后，下方浮条显示 门/需要物品，并提供「编辑来源地点」「删除这条出口」。

「删除这条出口」走已有的 `PUT /api/v1/worlds/{id}/locations/{location_id}`：
把该地点的 `exits` 过滤掉目标项后整体提交，返回的新世界直接替换本地状态并刷新 `/map`。
后端 `world_editor.upsert_location` 会照常做引用校验，非法出口仍然被拒绝。

### 节点

- 双击节点 → 打开已有的 `ResourceForm`（地点编辑），复用原有增删改，不另造表单；
- 节点上显示 id、物品数、实体数、出口数，起点用高亮边框；
- 拖动时用 `setPointerCapture`，松手才写 `localStorage`，避免拖动过程反复落盘。

## 为什么不做"拖拽连线建出口"

建出口需要选目标地点、可选的标签、门、所需物品，还要防止重复边和自环。用表单
（`ResourceForm` 里已有的出口行编辑）表达这些约束比拖拽更准确，出错信息也更清楚。
拖拽建边留到有明确需求时再做。

## 验证

- `npm run build` 通过（`dist/assets/index-BLcW-6mJ.js` 776.77 kB / gzip 239.32 kB）。
- 后端 `GET /api/v1/worlds/{id}/map` 已由 `backend/tests/api/test_routes_engine.py` 覆盖，
  前端只消费该响应，没有新增后端接口。
- 手工验证路径：世界工作室 → 世界地图 → 拖动节点 → 双击地点改描述 → 保存 → 点连线 → 删除出口。

## 已知限制

- 布局是分层的，不是力导向；复杂世界（>40 个地点）需要手动拖一次再存。
- 位置只存在当前浏览器，换机器或清缓存会回到自动布局。
- 还没有"新增出口"的可视化入口（走地点表单）。
